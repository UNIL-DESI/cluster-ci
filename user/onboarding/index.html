    Researcher Onboarding Guide

    Welcome to the Cluster-CI platform. This guide walks you through the step-by-step onboarding process to set up your credentials, install the CLI client, and configure your repository for running experiments on the cluster.

    Web Dashboard: http://130.223.73.209:5000/

    VPN Required

    The Web Dashboard is hosted on the cluster headnode and is accessible exclusively from the UNIL campus network or when connected to the UNIL VPN (Pulse Secure / Cisco AnyConnect). If the dashboard does not load, ensure your VPN connection is active.

    1. Joining the GitHub Organization & Creating Your Research Repository

    Cluster-CI leverages GitHub for authentication, access control, and GitOps job scheduling.

    1. Request Organization Membership: Contact your administrator (hjamet) to receive an invitation to the UNIL-DESI GitHub organization.
    2. Accept the Invitation: Check your email or visit github.com/UNIL-DESI to accept the invitation.
    3. Create Your Research Repository: Create a new repository on the UNIL-DESI organization for your research project (or clone your own existing research repo locally).

    4. Install the Cluster-CI Client: Open your terminal at the root of your local repository and run the install script:

      curl -sSL https://raw.githubusercontent.com/UNIL-DESI/cluster-ci/main/install.sh | bash

      Windows users must run the installation command inside a Git Bash terminal: 

      curl -sSL https://raw.githubusercontent.com/UNIL-DESI/cluster-ci/main/install.sh | bash

      This script injects the GitHub Actions workflow (.github/workflows/cluster-ci.yml), the .cluster-ci configuration file, the pre-commit hook, and the cluster-run CLI into your repository. Note that researchers only use cluster-run for their day-to-day workflow (cluster-update is reserved for platform administrators).

    2. Configuring Your Personal SSH Key

    To push code and interact with your repository on GitHub, ensure your public SSH key is registered under your personal GitHub settings:

    1. Generate a secure key pair if you do not have one: 
      ssh-keygen -t ed25519 -C "your_email@example.com"
    2. Add your public key (~/.ssh/id_ed25519.pub) to your GitHub account: Settings -> SSH and GPG keys -> New SSH Key.

    3. GitHub Repository Secrets (Environment Variables)

    If your pipeline needs external credentials (e.g. HuggingFace tokens, GCP service account keys, API tokens), you can securely inject them as environment variables via GitHub Repository Secrets.

    How to Add a Secret

    1. Go to your research repository on GitHub.
    2. Navigate to Settings → Secrets and variables → Actions.
    3. Click New repository secret.
    4. Enter a name (e.g. HF_TOKEN, GCP_CREDENTIALS, WANDB_API_KEY) and paste the secret value.

    How Secrets Are Injected

    All Repository Secrets you define are automatically injected as environment variables inside the Docker container when your pipeline runs on the cluster. For example, if you create a secret named HF_TOKEN, your Python code can access it via:

    import os
hf_token = os.environ["HF_TOKEN"]

    The injected workflow (cluster-ci.yml) passes all secrets to the cluster using ALL_GITHUB_SECRETS: ${{ toJSON(secrets) }}, and the orchestrator (submit_job.py) parses and injects each secret as an environment variable in the execution container. The only secret excluded from injection is GITHUB_TOKEN, which is automatically managed by GitHub.

    4. Configure Your Project

    Before running your first job, you need to set up two files at the root of your repository:

    .cluster-ci — Hardware & Runtime Settings

    This file is created automatically at the root of your repository by the installation script with minimal lightweight defaults:

    # Default template generated by install.sh
REQUIRED_RAM=2GB
REQUIRED_VRAM=0GB
MAX_RUNTIME_HOURS=1

    For GPU-accelerated workloads and deep learning pipelines, edit the file to declare the appropriate hardware allocations:

    # Example configuration for deep learning training
REQUIRED_RAM=16GB
REQUIRED_VRAM=24GB
MAX_RUNTIME_HOURS=4
# Optional: PARALLEL_STAGES=true
# Optional: PRIORITY=normal

    → See the Configuration Reference and Per-Stage Resources Guide for complete details on resource settings.

    dvc.yaml — Experiment Pipeline

    Define the steps of your experiment in a dvc.yaml file. The cluster executes these steps automatically:

    stages:
  train:
    cmd: python3 src/train.py --epochs 10
    deps:
      - src/train.py
    outs:
      - models/model.pt
    metrics:
      - reports/eval.json: {cache: false}
    plots:
      - reports/loss.png: {cache: false}

    → See the DVC & Storage Guide for detailed instructions.

    5. Two Execution Modes for Researchers

    Researchers only use cluster-run in their day-to-day workflow. There are two primary execution modes available depending on your task:

    Mode 1: Interactive Execution with cluster-run

    Submit jobs directly from your local terminal with real-time feedback: 

    cluster-run
    * Live Log Streaming: Directly streams stdout and stderr from the executing worker container to your terminal. * Graceful Interruption: Pressing Ctrl+C sends a clean cancellation signal (POST /api/jobs/{id}/stop) to the cluster, stopping active containers cleanly. * Automatic Results Sync: Metrics and plots generated by your stages are automatically pulled back into your local workspace upon completion.

    Mode 2: Disconnected Background Execution via Git Tag

    For long-running training jobs that take hours or days, trigger the cluster via a Git tag without keeping a local terminal open: 

    git tag -f cluster-run && git push origin <branch> --tags
    (Or use git tag -f cluster-run-skip-code && git push origin <branch> --tags to skip invalidating cached DVC stages for code-only modifications).

    • Fire and Forget: You can safely close your terminal, disconnect your laptop, or turn off your computer. The calculation continues running uninterrupted on the cluster.
    • Dashboard Monitoring: Follow progress, stage status, GPU telemetry, and live logs anytime on the Web Dashboard (VPN required).
    • Retrieve Results Later: When the experiment completes, retrieve your metrics and models using git pull --rebase origin <branch> and cluster-run sync.

    Once you have completed this onboarding, you are ready to run your first job. Proceed to the Command-Line Client Guide.

    [!TIP] Working with Sensitive Data? If your dataset is confidential or cannot be uploaded to GitHub, request Headnode SSH access from Henri Jamet (henri.jamet@unil.ch) and refer to the Sensitive Data & Local Execution Guide.
